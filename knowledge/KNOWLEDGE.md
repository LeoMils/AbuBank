# AbuBank Knowledge System — Manifest (single source of truth registry)

This is the index Claude Code MUST load before any implementation or evaluation
task. Each domain has ONE authoritative file. A fact lives in exactly one place —
never duplicate it elsewhere; link/point to the authority instead.

## Authorities (the only place each fact may live)

| Domain | Authority file | Format | Consumed by | Edit via |
|---|---|---|---|---|
| Family relationships/people | `knowledge/family_data.json` | JSON (machine source) | runtime `familyGraph.ts`, `generate:memory` | skill `add-family-member` |
| Per-person family records | `knowledge/family/people/*.yaml` | YAML (generated view) | humans / Claude | regenerate via `generate:knowledge` |
| Personality / daily life | `knowledge/martita_personality.yaml` | YAML | `generate:memory` | edit directly |
| Product definition | `knowledge/product.yaml` | YAML | Claude / docs | edit directly |
| Companion behavior & tone | `knowledge/behavior.yaml` | YAML | Claude / enforcers reference | edit directly |
| Production rules & gates | `knowledge/production_rules.yaml` | YAML | Claude / war-room | edit directly |
| AbuAI identity (constitution) | `knowledge/abuai_identity.yaml` | YAML | Claude | edit directly |
| Birthdays / memorial dates | `knowledge/family_data.json` (`birthday`, `deceased.memorial_date`) | JSON | runtime, reminders | skill `add-family-member` |

## Generated artifacts (NEVER edit by hand)
- `memory/*` — generated by `npm run generate:memory` from `family_data.json` + `martita_personality.yaml`.
- `knowledge/family/people/*.yaml` — generated by `npm run generate:knowledge` from `family_data.json`.
- `knowledge/family_context.md`, `knowledge/family_verification.md` — human-readable derivations.

## Anti-duplication contract
- Family facts: ONLY in `family_data.json`. Do not restate relationships/birthdays in code, docs, or memory by hand.
- Product/behavior/production/identity: ONLY in their `knowledge/*.yaml` authority. CLAUDE.md and docs may
  POINT to them but must not re-encode the canonical lists.
- The validator (`npm run validate:knowledge`) fails if a registered authority file is missing, if a
  per-person file drifts from `family_data.json`, or if a canonical marker appears in more than one authority.

## How to use (Claude Code)
1. Before ANY implementation/eval task: read this manifest, then the relevant authority file(s).
2. To change family: run skill `add-family-member` (edits `family_data.json`, regenerates memory + per-person,
   validates). Never hand-edit `memory/*` or `knowledge/family/people/*`.
3. To change product/behavior/production/identity: run skill `update-knowledge` (edit the YAML authority + validate).
4. Validate: `npm run validate:knowledge` (also runs as part of `prebuild`). Regenerate: `npm run generate:knowledge`.
